## What was removed or replaced

- Removed Maxer and Rebirth Skip definitions and grant branches. RebirthProfile no longer accepts a skip bypass; an extra boolean cannot ignore its coin threshold.
- Removed Mutation Luck from Passes and every sale route. Its pure calculator remains in RollEngine with an explicit pending-policy-review comment. Game.MutationLuck returns 1 unconditionally; MutationLuckEnabled remains false.
- Replaced ExtraPlots and Extra Growth Pad with Third Growth Pad. No active entitlement grants production plots or an early second pad.
- Replaced the repeatable 60-second Starter Pack with one account-owned 30-minute reference bundle, two Grow10 credits, Sprout Planter and Bud title.
- Reused the existing Journal cosmetic inventory, equip/clear, Medal shop and like/Index rewards. Added four fixed cosmetics and an eight-item featured selection; existing earned cosmetics/titles were preserved.
- Shield remains absent from developer products, as completed in the previous task. Its coin defense remains in Chill-off Sabotage.

## Third pad and migration

Profile schema is 8 in the existing BuildATree_v1 namespace. Growth, Growth2 and Growth3 retain independent immutable identities, durations, heights, progress and settlement times. World indices are 7, 8 and 9, separate from production plots 1-6. GrowthService, shared GrowthPads, PlacementRules, ready HUD, selection/replacement, FIFO queue, watering selection, Grow Now brackets, reusable credits, event transitions, offline growth, height records and Ascension cleanup all support pad 3. Queue capacity is two, or three when pad 3 is available.

The new pass activates after the first Ascension, so it does not replace or skip the free second-pad milestone. The same third pad and queue increase are earned free at the third Ascension. Queue entries still start only after explicit placement vacates a pad; ready trees never auto-replace producers offline.

Migration converts old ExtraPlots/GrowthPad ownership to ThirdPad ownership and records migration-only LegacySecondPad access. That flag preserves existing owners and saved second-pad trees; no new pass grants it. Existing producing plot indices are preserved by raising the saved coin plot level as needed, without granting old empty bonus plots. Parts, raw stats, mutations, in-flight durations/heights, queue snapshots, Saplings, old collection discoveries/claims, medals, likes, settings and receipt history are retained.

Historical StarterPack entries in PurchaseLog mark ProductsOwned.StarterPack consumed, add the two cosmetics and never replay coins or credits. Historical amounts are not invented. Cosmetic Bundle owners receive the two inventory items. ProductsOwned, unused credits, cosmetics, pass ownership, spending records and server quotes survive Ascension. Wallet coins and temporary lucky boosts continue to reset as before. Migration is idempotent and there is no profile wipe.

## Reference income and stacking

Coin packs now use Journal reward reference income rather than Game.Income. Reference includes earned trees, Leaf Power, Saplings and claimed collection bonuses, excludes temporary weather, paid effects and pets, remembers the seven-day best, and is capped at 100,000 coins/second. A prompt saves its server quote and context before calling Marketplace. Starter Pack caps at 50M coins; each coin pack caps at 100M. At a fresh starter producer the bundle quotes 18,000 coins rather than the old 600. At the reference cap, Small/Medium/Large quote 6M/30M/100M. An unmatched non-Starter coin receipt can use a delivery-time server quote; Starter requires its saved quote. No client-provided amount or income is accepted.

Double Coins applies exactly once after all other fruit-value factors. Growth rate is (1 + pet growth) x Double Growth x eligible private factor x one weather event x active pest factor. Double Growth is 2, private is 1.25, Rain is 3 and Windstorm is 5. Weather events replace each other. Thus paid growth plus private Windstorm is 12.5 before pets/pests, not instant completion. All three pads share the rule. Saved temporary weather rates are stripped before offline settlement, and event-deadline splitting remains.

Super/Ultra preserve the existing replacement rule: the selected 2x/4x factor replaces the active factor and adds 15 minutes to remaining duration. Buying Super during Ultra can lower active luck. Passes descriptions and numeric pre-purchase Odds previews disclose this. Rarity luck never changes mutation or egg probabilities.

## Policy and receipt review

Roblox requires numerical outcome disclosures and account-policy treatment for direct and indirect paid random items, including luck modifiers and currency used for random items. This build retains the existing conservative policy gate for every paid gameplay item and exempts only fixed cosmetics. Unknown/restricted accounts fail closed. No new paid randomized grant was added. See [Roblox paid random items guidance](https://create.roblox.com/docs/production/monetization/paid-random-items).

Prompts check persistence, global enable switch, nonzero configured ID, ownership, eligibility and the optional spending budget. Starter ownership blocks repeated prompts. Developer receipts save reward and PurchaseId together through the existing session-owned DataService transaction. Duplicates acknowledge committed receipts without another grant, including after an account becomes restricted. A new restricted receipt stays pending; it does not silently consume the paid reward. Cancel callbacks grant nothing and only clear matching pending requests, retaining server quotes for valid late receipts. Pass callbacks verify ownership with Marketplace and durably record entitlement/spending once. Receipt CurrencySpent is platform-owned; draft prompt budgets use server-configured proposals. Actual live price and regional-price budget reconciliation still require review before any IDs are configured.

Session ownership loss, UpdateAsync reentry/failures and throwing grant isolation remain covered by SaveFaults. Studio-only injected Marketplace/backend tests exercise production purchase/persistence code without real network purchases. These results do not certify actual Marketplace delivery. [Roblox receipt reference](https://create.roblox.com/docs/reference/engine/classes/MarketplaceService#ProcessReceipt) supports using server receipts for durable delivery.
